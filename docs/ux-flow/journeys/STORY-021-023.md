## Take-away Pass

**Empty Files (lead-observed, no screenshot)**

- Title "Give your first agent a home." with "Create your first drive ↗" and a 3-step strip (01 Create a drive, 02 Save your key, 03 Connect an agent). The strip is a useful map. Keep, but it is not interactive (suspected), so step 03 is not a button. The arrow glyph "↗" implies an external link on a button that opens a dialog (#14, clarity).

**Create a drive dialog**

- Fields: Drive name only. Minimal. Could be prefilled with "My first drive" (accept in one click). Do this (#2, #3).

**"Your drive. Your key." dialog**

- Textarea with key + "Save recovery key" + warning box + checkbox + disabled "Continue to drive". Four things competing: copy the text, download the file, tick the box, continue. The same secret appears in the textarea and in the JSON file (catalog edge case). Collapse: one primary "Download recovery key", a secondary "Copy", and the checkbox enabling "Continue". Or, make the checkbox implicit: enable "Continue" after the download or copy click (the app can at least verify the user clicked) (#4).
- Warning box repeats what the dialog heading and the earlier dialog text already say ("the server cannot recover it" vs "Losing this key means losing access"). One statement is enough (#12).

**Agents tab (03-console-agents.jpg, populated)**

- Shows each agent with "2 active keys" and a "Revoke access" button, and a "1 agents" badge (grammar slip: "1 agents"). It is the only place to see agents, but it can't create a key for an agent; the user must go to another tab. A per-agent "New key" action here would remove the tab hop (#13). Suspected: the catalog does not list such an action.

**API keys page (04-console-api-keys.jpg)**

- Heading, subtitle, "Refresh", "+ New API key", list, then a large terminal card. The terminal card is as heavy as the list itself and uses 4 shell lines plus 2 prose paragraphs (#10, #11).
- `agent-drive login --api https://your-agent-drive-host`: measured placeholder; the console knows its own origin and could print the real URL. This is the biggest removable burden (#3: don't ask for what you know).
- `read -rs` twice is safe but needs two separate pastes in two prompts, and `agent-drive mcp` in the same block is a different task (using MCP) mixed into the login steps.
- "Refresh" button on every page: the list reloads after each action, so it is chrome (suspected, not verified).
- Row "trace-bot weekly archive / trace-bot · read, write / agent-traces" shows the agent name three ways (key label, agent, scopes) (#12); minor.

**Save your API key dialog**

- Secret in textarea, checkbox, "Done". Fine, minus the checkbox as discussed. No copy button mentioned in the catalog steps ("Copy the token into her password manager"), suspected: the user selects text by hand. Add one-click Copy.

## The Simpler Version

Target: about 7 interactions, one decision (names).

1. Empty console: one button "Create your first drive". The name dialog opens prefilled ("My drive"), press Enter.
2. Key dialog: "Download recovery key" (primary). "Continue" enables after download or copy. No checkbox.
3. Console now says "Next: connect an agent" with a single button that opens one combined dialog: Agent name (and key label defaults to the same). Drives = the one drive, permissions = read+write; a link "Change access" reveals the rest.
4. Create produces the API key dialog (copy button, "Done").
5. Show a connect block with the real origin pre-filled: `agent-drive login --api https://agent-drive.vercel.app`.

Concrete changes, in order of payoff:

1. Fill the real origin in the terminal snippet (`console.tsx:860`; use `window.location.origin`). Fixes a copy-paste failure for every new user.
2. Merge "create agent" and "create first key" into one dialog on the first run; do not jump tabs (saves about 4 interactions).
3. Default the key label to the agent name; collapse permissions behind "Change access", leaving only "manage" off.
4. Replace the two "I saved ..." checkboxes with "Continue" enabled after copy/download (keep a checkbox only for the drive key if you want a hard stop).
5. Add a Copy button next to both secrets (verify it exists; not in screenshots).
6. Prefill the drive name.

## Clarity Issues

- "Drive key", "recovery key", "API key", "key" are used for two different secrets. "Save recovery key" button, "I saved my drive key securely" checkbox, "Your drive. Your key." title: recovery key = drive key (same file). The API key page then says "Decryption keys and API keys are different" which introduces a third term. Pick: "drive key" (decrypts files) and "API key" (lets an agent in), and rename the button "Download drive key". (#14, from catalog and 04-console-api-keys)
- "Agent identity" (03-console-agents heading "Agent identities") vs "agent". "Revoke access" on the agents page vs "Revoke" on keys; revoking an agent kills all its keys, but the label does not say so. Suspected from "2 active keys".
- "manage — account-wide administration; use sparingly" (lead): the jargon "manage" does not say what a leaked key could do. Suggest "Admin: can create and revoke keys for the whole account".
- Notice "Agent created. Create an API key to connect it." is clear, keep.
- "Create your first drive ↗": the arrow signals an external link on an in-page dialog.
- "Personal workspace / Operator console" (02-console-files sidebar) vs "Create your workspace" on landing; "workspace" also is the sidebar group label "WORKSPACE". The product's actual objects are drive, agent, key.
- "Key required for downloads" under the drive selector (02-console-files) is clear, but its fix button reads "Load drive key" while the creation flow called the same secret "recovery key" (see above).
- "1 agents" in 03-console-agents: missing singular.

Functional bugs, one line: the terminal host placeholder (`console.tsx:860`) is a correctness bug, not just wording; no client-side check that at least one scope is ticked (catalog edge case).
