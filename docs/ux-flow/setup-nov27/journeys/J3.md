## 2. Take-away pass per screen

**Files banner, "Set a passphrase and agents will add every drive's key to your account — then each one opens here automatically. Set up"** (035 step-3.png). One clear action (`Set up`), but it is small link text next to a large orange `Connect an agent`; the loudest element on the page is not the next step for this journey (heuristic 9). Keep, but make `Set up` a button.

**Settings page "Activity & deletion"** (036 step-1.png). The Passphrase card is the third block below an Activity table. Take-away: nothing here is needed for the passphrase except the fingerprint line, and the card's only button is `Manage in Files`, which sends the user back where they came from. The CLI says "under Settings" (035 step 1, 036 step 2); the page is titled "Activity & deletion" and "the word 'Settings' appears nowhere on it" (036 walk). Fingerprint sits in small grey prose with a trailing comma (036 step-1.png), no copy button. Candidate for removal as a setup destination: show the fingerprint where the user already is.

**Set up passphrase unlock dialog** (035 step-5.png). Strong. One generated code, Copy, one checkbox, Create, one secondary `Use my own passphrase`. Create is visibly disabled until the tick. Copy line "If you lose it you can reset it, but every drive must be added again" is useful. Already near minimal. Removable: the two-step "copy then tick" could be one (Copy sets the tick), suspected, small.

**Key chip menu** (035 step-7.png, 042 step-2.png). Seven stacked equal-weight buttons: Load key, Download recovery file again, Lock, Lock this browser, Add a passkey, Change passphrase, Forgot or exposed passphrase?. No primary action when Unlocked (heuristic 9). The status sentence plus fingerprint plus backup line state three facts in small grey type. `Load key` is useless when unlocked and the agent has nothing to load. Collapse: keep Lock (one button), put Change/Forgot/Add passkey under "More". Fingerprint is only useful for CLI pinning, so it belongs with a Copy button, not as 11px grey text.

**Load-key dialog** (035 step-8.png, 039 step-1.png). Three jobs in one dialog: choose a file, paste a key, or run one of two CLI commands. The lower paragraph is about 7 lines with two Copy buttons and a `Set up passphrase unlock` button in the middle of prose (039 step-1.png). It repeats the seal paragraph in every Load-key dialog regardless of whether a passphrase exists (039 Flow Log). Takes away: collapse the CLI paragraph into one line "Ask your agent: `agent-drive credentials export --to <file>`" with one Copy; the seal path is only for users who want passphrase unlock and belongs in the post-setup banner.

**Unlock dialog** (038 step-2.png, 042 step-2.png). Clean: one field, one checkbox, `Unlock` plus a secondary. Problems: no `Forgot passphrase?` link even though this is where the user gets stuck; the black passphrase field with no visible text; `Keep this browser unlocked` ticked by default next to copy that says "The keys stay in this browser only" (042 step-2.png), which reads as reassurance. Information twice: none.

**Reset dialog** (038 step-5b-enabled.png). Headline copy states "removes every drive from it" and "Files are not deleted" in the same breath; the danger button reads `Reset and remove all drives` which contradicts the reassurance. Walker measured the disabled button at full opacity. Take away: rename to `Reset passphrase`; state first "Your files are not deleted."

## 3. The simpler version

Ideal for the first-time owner, passphrase path (target 5 steps, vs catalog 6 and measured 11):
1. Agent finishes login and prints: "Open <console url>/keys to set a passphrase" (a link to the real page, not "Settings").
2. Click `Set up`, copy the generated passphrase, tick, `Create` (one dialog; already minimal).
3. On the same success notice, show the fingerprint with `Copy seal command` that already contains `--fingerprint "<print>"`.
4. Paste the command in the terminal, `drv_...: sealed`.
5. Click a file; it opens.

Concrete changes:
- CLI warning text and Load-key help point at the Files page key menu, not "Settings" (naming drift; see 4). **S**
- The post-setup notice and key menu show the fingerprint with a Copy button, and the copied seal command includes `--fingerprint`. This removes 035 steps 8-11 (about 4 interactions). **M**
- Add `Forgot your passphrase?` to the Unlock dialog and drop the Unlock -> recovery-file loop. **S**
- Reset: message "Passphrase reset. Add your drives again: run `agent-drive account seal --repin --fingerprint "<print>"`" with Copy, shown right after Create. **M**
- Collapse the chip menu to Lock plus a "More" group; make `Lock this browser` the only lock when a key is stored, or make `Lock` clear the stored key. **M**
- Default `Keep this browser unlocked` to off (or add a one-line explanation); on the setup path ask the same question. Suspected safer default; a product decision. **S**

## 4. Clarity issues

- **"Settings" does not exist.** CLI strings and dialogs say "under Settings" (035 step 1, 038 step 3), the page is "Activity & deletion" (036 step-1.png), and passphrase setup is not there. Naming drift across CLI, dialogs, docs (catalog edge cases for 035).
- **Fingerprint vs "Verification code"**: both are four groups of four hex digits. Measured: using the login code gives a mismatch error (035 step 11). Labels should be visibly different, and the error could say "that looks like the login verification code".
- **"Unlocked" before anything is unlocked** (035 step 7, 035 step-7.png: "Unlocked" with "Drives you added to your account open when you use them").
- **"Key needed", "Load key", "recovery file", "credentials export", "account seal", "pin", "repin"**: five names for related ideas. Only the CLI uses "seal" and "pin"; the console says "add to your account". The Load-key dialog uses both in one paragraph (035 step-8.png).
- **"Choose recovery file" accepts a credentials bundle** without saying so (039 step 4).
- **Reset copy**: "removes every drive" vs "Files are not deleted" and a button that says `Reset and remove all drives` (038 step-5b-enabled.png).
- **Lock vs Lock this browser** have no explanation; observed that `Lock` does not survive a reload (042 step 3) while the label implies safety. This is a behaviour gap more than a wording one.
- Error `--fingerprint must look like "a1b2 c3d4 e5f6 7890"` does not name the comma (036 step 2). **S** to improve by stripping trailing punctuation instead.
- Already good: the generated-passphrase dialog, wrong-file errors in the recovery dialog ("red, inline, helpful", 039 step 4), and the "Passphrase set up" notice. The `credentials export --to <file>` fast path counting as a backup immediately is excellent (039 step 3).

## Top proposals
1. Put fingerprint + Copy in the success notice and key menu, and include `--fingerprint` in the copied seal command (removes about 4 steps). Effort M.
2. Add `Forgot passphrase?` to the Unlock dialog, and a post-reset message with the `--repin` command. Effort S/M.
3. Shrink the Load-key dialog to file + one agent command; rename "Settings" references to the real page. Effort S.
