## 1. Friction scorecard

Decisions a default could carry (each counted):

1. "Agent-only — never add this drive to passphrase unlock" checkbox, shown to a user who has no passphrase [O: SETUP-004 step-1-new-drive-dialog.png]. Hesitation recorded in SETUP-015, 034, 047. 3 walks, same hesitation [M].
2. Agent identity must be created before an API key, and a drive before an agent [M: SETUP-047 step 2, "path is drive -> agent -> key (3 creation steps before the key)"]. User decides names for 3 objects (drive, agent, key label).
3. API key permissions: 5 checkboxes (read, write, delete, share, manage) [O: SETUP-015 step-8.png]. Defaults are right (read, write ticked); the choice is rarely needed.
4. Drive name, agent name, key label: three naming prompts for one hand-off [M].

Re-entry (data the app already has):

1. Drive id and drive key must be hand-copied into env vars [M: SETUP-015 flow log "Re-entry"; SETUP-047 flow log]. The console snippet prints the real drive id but not the key [O: SETUP-047 step-16.png].
2. On /connect the user re-supplies the key or file the console just saved, and retypes the verification code [M: SETUP-034 flow log].
3. SETUP-015 step 12: `credentials import --from <the console's recovery file>` fails with "Not a valid Agent Drive credentials bundle." The file the console just produced cannot be used by the CLI [M].

Confirmations guarding nothing:

1. "Did the recovery file save?" then "I saved it" [O: SETUP-004 step-3-saved-confirm.png]. This guards a real risk (key loss), but it is a self-report: the app cannot see the file. It also repeats "Without it nobody, including us, can open this drive." a second time in the same dialog [M: SETUP-047 step 4; O: step-3-saved-confirm.png shows it in both paragraphs]. Keep the guard, drop the repeated sentence.
2. "I saved my API key securely" checkbox plus disabled `Done` [O: SETUP-015 step-9.png]. The key is shown once, so a guard is defensible, but it is a checkbox AND a button: two actions for one acknowledgement.

Dead ends and hesitations:

1. Recovery file is a dead end for the CLI (see re-entry 3) [M].
2. `agent-drive check` after login says "There is no usable drive key on this machine. Run `agent-drive login` again." Logging in again cannot fix it [M: SETUP-015 step 11].
3. After /connect approval the CLI says "Set a passphrase in the console..." and `check` fails with "drive key not backed up", although the owner saved the file [M: SETUP-034 step 10].
4. API-key panel says "Run the CLI from the repository after building it." to users who installed from npm [O: SETUP-015 step-7.png; SETUP-047 step-16.png].
5. `Create API key` button greys out for about 8 s with no progress [M: SETUP-047 step 8; dev server, so timing is suspected for production].
6. After "I saved it" the console jumps to Files; a user who started from API keys must navigate back [M: SETUP-047 step 5].
7. CLI `login --token-stdin` prints raw JSON, no "Logged in" sentence [M: SETUP-015 step 10].
8. Console header banner "Set a passphrase ... Set up" competes with "New drive" on the first screen [O: SETUP-015 step-1.png]; unexplained to a user with no drive [M: SETUP-034 step 1].

## 4. Clarity issues

Jargon and labels assuming knowledge:

- "Agent-only — never add this drive to passphrase unlock": passphrase unlock is explained nowhere on the screen [O: SETUP-004 step-1].
- "Drive key", "recovery file", "API key", "adcred1 bundle", "agent identity": five names for related secrets. The API-key panel itself says "Decryption keys and API keys are different: neither replaces the other" [O: SETUP-015 step-7.png], which is the confusion in one sentence.
- "Connect without sharing your identity." means nothing to a first-time reader [O].
- "manage — account-wide administration; use sparingly" is the only permission explained; delete and share are bare words [M: SETUP-047 step 7].
- "Forget key" has no explanation [M: SETUP-034 step 7].
- "Set up" (header) vs "Set up Agent Drive:" (line) vs "Set up a drive myself" (catalog) vs `New drive` button: "set up" names three different actions [O: SETUP-015 step-1.png].

Naming drift (web / CLI / docs):

- Recovery file (web) vs credentials bundle (CLI: "Not a valid Agent Drive credentials bundle.") vs key file (web /connect: "load a key file") vs `.key.json` [M: SETUP-015 step 12, SETUP-047 step 10].
- "Verification code" (CLI and /connect) vs pairing code (console onboarding "The agent shows a pairing code") vs "Check that the code matches: XXXX-XXXX" (a second short code in the same login) [M: SETUP-034 step 9; O: SETUP-034 step-10b.png shows both "PNRR-XZJR" and a "Verification code" field].
- "Create API key" button vs `+ New API key` vs `+ New agent` vs "Create agent": create/new used interchangeably.
- API URL: console snippet gives `--api http://localhost:3811` while the story and docs give `.../api`; the CLI accepts both in login but earlier error says only "refused the login request: 404" without `/api` [M: SETUP-034 step 9; SETUP-047 step 10 says both work, so inconsistent between walks].

Already good (do not change): inline error on /connect with no key; "Recovery file saved. Create an API key to connect it." hand-off banner [O: SETUP-015 step-7.png]; "This secret is shown only once" copy; prefilled sensible API-key defaults; the approved page.
