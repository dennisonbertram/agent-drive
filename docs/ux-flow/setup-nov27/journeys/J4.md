## 3. The simpler version

Ideal steps (grant to second laptop agent), 5 instead of 7-8:

1. New agent: `agent-drive login --name codex-desktop`. Prints link and verification code.
2. Human tells the granting agent the two codes (one message).
3. Granting agent: `agent-drive grant <code> --verify "<v>" --write-path /codex`.
4. Human opens link, sees "Share `research-notes` (read, write in /codex) with codex-desktop", types verification code, Approve.
5. Codex CLI prints "Logged in ... Back up with `agent-drive credentials export --to <file>` or you are done if this agent lives on a durable machine" and `check` already passes.

Concrete changes:

1. Make `/connect` for a login with no grant say so: "No drive has been offered yet. If another agent is about to share one, wait. Approving now creates a new empty drive." (S, fixes the trap, S043/step-5.)
2. Let a granted or env-bundle agent count as backed up when the granter holds the drive key, or make `check` say "this agent holds a sealed copy; back up is optional here". Removes the forced extra step in W043 step 8 and the web/CLI contradiction in W044 step 8 ("Key needed" vs "Key backed up (env)"). (M)
3. Issue flow: print only the part after `=` for `--stdout`, or accept the `AGENT_DRIVE_CREDENTIALS=` prefix in the sandbox. Removes the failed first CI run (W044 step 5). (S)
4. Surface delegate: show the checkbox outside Details, and make the delegate-missing error say "Run `agent-drive login --name "<same name>"` again and tick ..." and use the page's real wording (W050 step 1 notes "Optional" heading does not exist). (S)
5. Backup default: when none is chosen, recommend one ("`--to <file>` works everywhere; use 1Password or clipboard if you prefer") rather than "Offer these choices in this order" (W027, catalog 028). (S)
6. Revoked-key CLI message: drop the key-backup warning when the real error is revocation; add "ask the owner for new credentials" (W045 step 6). (S)
7. Revoke dialog: add one sentence about the drive key still being known to the bundle holder (W045 gaps). (S)

## 4. Clarity issues

Jargon / assumed knowledge:

- "(env)" in "Key backed up 11/27/2026 (env)" (W044 step 8); "(stdout)" shown to a clipboard user (W026 flow log); `writePaths must be a canonical absolute POSIX path.` while the flag is `--write-path` (W044 step 4).
- "sealed the drive key" on /connect (S043/step-1): accurate, but the human never learns what to do with that fact.
- `slow_down` raw OAuth error, no wait time (W050 step 3).
- "Agent identities" / "Agent access" / "Agent-only" used for related things in console (S044/step-5, step-6; catalog 004 finding).

Naming drift:

- Checkbox: "Let this agent add other agents to its drives" (page, S044/step-2) vs "Let this agent add other agents" (docs/llms.txt, W050 step 1); CLI error says it is under "Optional" (no such heading).
- "Issued by" machine name vs agent name between Agents and API keys tabs (S044/step-5, step-6).
- "Revoke access" (agent) vs "Revoke" (key); dialog wording differs: only the key dialog says "This cannot be undone" (W045 step 4) although both are permanent.
- Drive named after first agent: Approved page says "the drive priya-mbp agent" (S043/step-4), so the drive and an agent share a name and the sentence is ambiguous. [O]
- Docs and home copy say "click Approve" with no verification code (F-SETUP-003-1, results.json); this journey's pages need the code.
- Dev-environment bottom panel "Run the CLI from the repository after building it" (W044 step 7) contradicts npm install used elsewhere (possibly local-dev only [S]).

Tone mismatch: CLI wrong verification code says "the request may have been tampered with" (W043 step 3); web says "Check the terminal again and type it exactly" (S043/step-2). The web version is correct for a typo; use it in the CLI and keep the tamper line only when the pairing code also differs.

Misleading error: unknown pairing code with correct `--verify` returns "Pass --verify with the verification code ... exactly as shown" (W043 step 3). [M]
