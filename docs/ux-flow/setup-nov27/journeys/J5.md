   - "Could not find an executable Instabox CLI in PATH or ~/.local/bin." with no definition of Instabox and no install link (056 step 1, 3). Catalog says the install is "not documented anywhere in this repo".

5. Decisions a default could carry, observed: 4.
   - Mount name (`coordinator`) is required on `connect`; the mountpoint is derived from it in every doc example (`$HOME/AgentWorkspaces/coordinator`).
   - `--root /workspace/project` is typed every time (docs step 2 screenshot).
   - `--persist`: a user who wants the mount to survive logins must know to add it; without it, closing Terminal drops the mount (catalog 051 edge case). Suspected 90% of users want persistence.
   - Wake-on-access default is on and the cost warning sits far from the flag (catalog 057 edge case).
6. Confirmations guarding nothing: 0 found. There are no confirmation dialogs in the walked CLI paths. (Approve agent page is a real security check, not friction.)
7. Hesitations, measured from walk reports: where to find the app (no web or console pointer), what Instabox is, where an m_... ID comes from, whether wake/status need Instabox.
8. Information stated twice, measured: `--help` lists mounts commands twice (051 finding F-04); the Finder app link appears in 4 places (catalog: docs/cli.md:20,240, native/macos/README.md:9, packages/agent-drive/README.md:38, skill) and nowhere in the web app.
9. Contradictions, catalog text: README "open it once" vs docs "Opening the app from Finder does not open a window".

## 3. The simpler version

Current (catalog, drive mount): download zip, drag to /Applications, open the app once, `mount`, open Finder, drop a file, Ctrl+C. 7 steps; plus login.
Current (live workspace): read docs, find m_ ID, mkdir parent, `connect ... --persist`, open Finder. 3-5 steps, but every failure path ends in a message that does not say what to do.

Proposed ideal:

1. `agent-drive mount` (no path). If the Finder app is missing, the CLI says "Agent Drive Finder is not installed. Download: <URL>. Drag it to /Applications, then rerun." (no ENOENT). Default mountpoint `~/AgentDrive`.
2. The mount runs as a background login service by default; the CLI returns and prints "Mounted. Open Finder > Locations > Agent Drive. Stop with `agent-drive unmount`."
3. User opens Finder and drops a file.
   For a live workspace: `agent-drive connect m_7f3a...` (optional `--root`, default `/workspace`; mount name and mountpoint defaulted from the sandbox) then Finder. Persist by default, `--foreground` to opt out.

Concrete changes, with effort:

- (S) Catch ENOENT on the helper and print the install message (051 F-01, evidence: walk-report step 5).
- (S) `connect --persist` failure either rolls back (as foreground connect does) or appends "Run `agent-drive mounts forget NAME` to retry" (056 F-01).
- (S) Error text for existing mountpoint: "Remove the empty folder and rerun" (055 F-02).
- (S) Make `mounts wake` and `mounts service status` work without Instabox, or fix the docs sentence (057 F-01).
- (S) Define Instabox once in docs/cli and link its install page; show where m_... is shown (055 F-03, 056 F-02).
- (S) Remove `--sandbox` from the `mounts add` help line or support it (055 F-01); dedupe `mounts` lines in `--help` (051 F-04).
- (S/M) Docs: split the Finder paragraph into numbered steps; add "Mount in Finder" to Quickstart and link it from the console empty state (051 F-02).
- (M) Persist by default for `connect`, with `--foreground` instead (the story's own ideal is `--persist`, so it is the 90% case; suspected, not measured).
- (M) Default `--root` and mount name/mountpoint so `connect m_...` is the whole command.
- (M) Make a missing login prompt `agent-drive login` inline during `mount`, and include "login" in the ideal-path count.
- (L) Ship the Finder app via the CLI (`agent-drive mount --install-app`) or a signed installer so step 1-2 collapse. Suspected benefit; needs release/signing work.

## 4. Clarity issues

1. "Instabox" is used without definition in CLI errors, `--help` and docs (056 walk step 3). Newcomer persona literally "has never heard of Instabox" (catalog 056).
2. "sandbox", "workspace", "Finder mount", "live workspace", "workspace service" are used for the same thing. The 055 walk note: "'sandbox' and 'Finder mount' used for a Linux-neutral error". Catalog: /docs/sandboxes uses "sandbox" for a disposable machine and says nothing of `connect`. Pick one noun ("workspace") and one verb ("mount").
3. `SANDBOX_ID` placeholder vs the real `m_...` form; the CLI error names the format but docs do not (055 F-03).
4. Docs claim wake changes "does not call Instabox", the CLI does (057).
5. "open it once" (README, skill) vs "does not open a window" (docs/cli): contradictory first instructions (catalog 051).
6. Error "Could not find an executable Instabox CLI in PATH or ~/.local/bin." under-lists searched directories (catalog 056, workspace-service.ts:159) and does not say how to fix it.
7. "Ignored a different API URL returned by the server." printed by login with no explanation (051 F-03).
8. Two login codes on the approve page with similar names: "pairing code" in the CLI, "Does this code match your terminal?" and "VERIFICATION CODE" on the page (screenshots/step-3.png). Suspected hesitation.
9. Command name drift: `mount`, `mounts add`, `connect`, `mounts service install` all create mounts; `connect` is the only one that takes `--sandbox`/`--root`, yet `mounts add` help lists `--sandbox` (055 F-01). Violates "one way to do one thing".

## Top 3 proposals

1. Turn every Finder/Instabox dead end into a message with the next command: app-missing (no raw ENOENT), Instabox-missing (define it plus install link), persist rollback or `mounts forget` hint (S).
2. Make `connect` persist by default and default mount name, mountpoint and `--root`, so one command with just the m_... ID is enough (M).
3. Add a Mount in Finder section to Quickstart and the console empty state, and rewrite the dense Finder paragraph in docs/cli as numbered steps (S).

Caveat: no success path was observed in any of these stories, so the step counts for the happy path are the catalog's, not measured.
