## 2. Take-away pass, per screen

**Capture dialog, no webhook yet** (059 step-2.png, 062 step-2.png)

- Removable or deferrable: the Local agents block (paragraph plus two commands) is not used by a webhook user. Collapse it, or put it second. The sentence "Check terminal output: capture may be disabled, uploads may be queued, or calls may not be captured." names three conditions without saying what to do or what the messages look like (059 step 2).
- Primary action: exactly one orange button, `Add webhook`. Good. The four small `Copy` buttons are secondary and quiet.
- Stated twice: no. (The topic notes feared a duplicated TLS sentence; 059 Flow Log confirms it appears once. Fine.)
- The TLS footer reads as general fine print below both sections; it is not needed to complete the task.

**Capture dialog, token shown** (059 step-3.png)

- The one-time secret (Headers) sits about 330px down, below Local agents, with the larger `Replace` button above it. The 807px dialog scrolls internally on an 800px window (059 step 3). The user's task ("copy these now") is not at the top.
- Missing, not extra: no "Done" or "Next: paste into OpenRouter" action, and no note that the `openrouter` agent was created (059 step 6).
- Info duplicated: the "Created today 18:04 / Active" row is shown above the one-time block. Two stateful rows for one thing; acceptable, but in 068 step 3 two tabs show an identical row, so it does not identify which token is current.

**Capture dialog, existing token** (064 step-1.png, 066 step-1.png)

- Shows `Created`, `Active`, `Replace`, `Revoke`. Clean. `Replace` is the bold button and the likeliest user intent when a token is lost, but also the most destructive (064 step 2: old token 401). Visually dominant action is the risky one with no hint text.
- Revoke is a small red text link (50x32 at mobile, 064 step 3). Acceptable for a rare action.

**Unlock dialog, passphrase** (060 step-4.png)

- Already minimal. One field, one primary `Unlock`, escape hatch `Use a recovery file instead`. The note "After you unlock, you can set up the OpenRouter webhook." is the only weak line: it suggests another click, but setup resumes automatically (060 step 5).
- "Keep this browser unlocked" pre-checked is a good default.

**Unlock dialog, recovery mode (non-agent-only)** (061 step-1.png)

- Fails the take-away test. The paragraph "No recovery file? An agent that has this drive's key can add it to your account: run `agent-drive account seal --drive <id>` on its machine ... re-run it with `--fingerprint` set to the account-key fingerprint under Settings" is a CLI tutorial inside a key-loading dialog. 061 step 1 notes the sidebar has no Settings item. Remove or move to docs; keep drop zone, `Paste a key instead`, and one "No file? Run `agent-drive credentials export`" line.
- The agent-only variant (061 step-5.png) is the clean model: drop zone, paste disclosure, one export command. Use it for both.

**Mismatch and empty-drive errors** (061 step-2.png, 062 step-2.png)

- Two dialogs hand the user off to each other. The unlock dialog accepts the wrong key silently, then the Capture dialog reports "This key does not open this drive's files. Retry" while the chip still reads "Key needed" (061 step 2). `Retry` does reopen the chooser (061 step 3) but does not say a different file is needed.
- On an empty drive a correct pasted key is rejected with "This drive has no files yet. Load its recovery file or credentials bundle so the key can be matched to the drive." (062 step 2). The user did nothing wrong.

**/traces empty state** (068 step-4.png)

- One sentence with a link to the dialog, one primary path. Good. It does not say OpenRouter traces land in `/traces/openrouter/<date>/` (068 step 4).

## 3. The simpler version

Ideal steps (unlocked drive with key): 1. `Capture...` 2. `Add webhook` 3. Copy the URL and headers (one button or two) 4. Paste into OpenRouter. This already matches the current 4 clicks. The target is the same click count with less reading and fewer ways to get stuck.

Concrete changes:

1. **Put the webhook first in the Capture dialog; collapse Local agents** under a "Capture a local agent instead" disclosure. Effort S. Evidence 059 step-2.png.
2. **Keep the token view top-aligned**: when a token is just issued, show the one-time URL and Headers block at the top, or a single "Copy URL and headers" button; add a final line "Created an `openrouter` agent to own these traces." Effort S. Evidence 059 step 3 and step 6.
3. **Add Replace guidance**: under the existing-token row, "Lost the header? Replace creates a new one. The old one stops working now. The URL stays the same." Show the URL for existing tokens (it is not secret, 064 Edge Cases). Effort S.
4. **Unify the key-mismatch path.** Catch a mismatch in the unlock dialog (as is already done for a different drive's file, 061 step 4: "That recovery file is not for this drive.") or at least make the Capture error say "Choose a different recovery file" with the button labelled that way instead of `Retry`. Effort M.
5. **Empty drive**: change the message to "This key cannot be checked on a drive with no files. Use the recovery file or a credentials bundle." Effort S. Or skip proof for pasted keys when the drive is empty (security decision; do not recommend without review). Effort M.
6. **Replace the long recovery-mode paragraph** in the non-agent-only dialog with the agent-only layout; move `account seal` and `--fingerprint` to docs. Effort S.
7. **Two-tab race**: after another token is issued, the older tab keeps showing a dead token (068 step 3). Refresh the row on focus, or add "Created <time>" to the one-time block and a note "A newer token replaced this one." Effort M.
8. **Revoke feedback**: one line after revoke, "Webhook revoked. Existing traces stay in /traces/openrouter/." Effort S.

## 4. Clarity issues

- Naming drift, observed: toolbar `Capture...`, drive menu `Capture traces...`, dialog `CAPTURE TRACES`, neighbouring `Traces` button opens the folder, not the dialog (059 Flow Log, 059 step-2.png). On mobile only the drive menu entry exists (059 step 7, 066 step 5). Pick one label for the button and the dialog, e.g. "Capture traces" everywhere; rename the folder button "Open traces".
- Wrong-key wording, observed, three versions: "That recovery file is not for this drive." (061 step 4), "This key does not open this drive's files." (061 step 2), and the console's "account copy is invalid" (topic finding 2, not reached by walkers). Use one.
- "Copy" buttons all read only "Copy" (059 step 4); accessible names are specific. Visible label could say "Copy URL" and "Copy headers".
- "Headers" with JSON `{"Authorization":"Bearer adw_..."}`: assumes the user knows OpenRouter's webhook form takes a JSON header object. Suspected; OpenRouter's form was not walked.
- "Privacy Mode" note appears only after the token is created (059 step 3), below the fold on small windows (059 step 5). Suspected risk: users leave for OpenRouter without seeing it. Move it above the Headers box.
- "Needs replacement" stale state and `Retry` on Clerk cancel: not walkable. Raw Clerk error text is shown in the dialog per code notes (topic finding 4), so cannot be judged. Flag for a real-Clerk walk.
- CLI login against the app origin returns "refused the login request: 404" which does not say the URL form is wrong (067 step 3). Observed once; may be environment specific.
- "No API keys" badge on the auto-created `openrouter` agent (059 step 6) reads like a defect.
