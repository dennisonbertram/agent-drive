# share (/s/[id]#key) visual audit, T1 Rack build, localhost:3230, 2026-11-04

Synthetic data: shares created with the CLI (put + share) against http://localhost:3230/api (seed in `helpers/seed.mjs`; keys redacted in `helpers/shares-redacted.json`). Shots in `shots/<viewport>-<state>.png` (+ `-full`), 4 viewports x 9 states (ready, ready-longname, missing-key, bad-key-format, not-found, expired, revoked-onload, wrong-key, loading). Measures in `audit.json` (36 keys: layout-audit + geometry-audit). Second opinions: `second-opinion.json` (muse-wonder, gemini-4-argon, 8 shots), verified below. Brief: `brief.md`.

Capture notes. Loading was forced by replacing `window.fetch` with a never-resolving promise, then setting the hash (observed state, not a real slow network). Wrong key = a valid share opened with another share's key, then Download clicked. Revoked and expired show on page load (the metadata call already fails); revoked does not wait for a Download click. The audit's `lowContrast` entries for the readout text (ratios 1.19 to 2.38) are false positives: the script measured against the page background instead of the dark window. Hand estimate: orange #ff7a45 and #d9d6cd on the near-black window are above 7:1, and #9a978e labels about 6:1.

## Excellent as is

- The ready state has one clear focal point, a full-width 48px orange Download button, and no scroll at any of the 4 viewports.
- Rack styling matches the T1 reference (chassis, sled, white label, dark readout, single signal orange); the only orange on the page is the LED, the readouts and the button.
- Mobile: 16px gutters, no horizontal overflow in any state (geometry audit `pageOverflowX` 0), long filenames wrap inside the label (`shots/375x812-ready-longname.png`).
- Distinct, specific headings for each failure ("Share link expired" vs "revoked" vs "not found"); the LED and heading change with state.
- Focus ring on Download is clearly visible; touch target 48px.
