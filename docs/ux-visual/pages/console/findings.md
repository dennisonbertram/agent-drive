## Overall judgment: cloud drive or developer table?

It reads as a developer table. The Files tab is a flat 5-column table of full paths (`/inbox/x/2026-11-01.jsonl` repeated five times), with no folders, no file-type icons, no sort, no selection, no upload, no new folder, no rename, no preview. The only orange primary on the page is "+ New drive", so the main action of a file browser is creating a drive, not working with files. Mono paths, uppercase mono labels, UUIDs and a "key required" gate on every row push it toward an ops console. The shell itself is clean and consistent (sidebar, drive strip, spec-sheet styling, one-screen layout at 1440), and the dialogs are tidy. What is missing is the file-browser model: hierarchy, scanning aids and file-level primary actions. The mobile Files view is a 4,800 px scroll of 174 px cards.

## Per viewport x state verdicts

- 1440 Files, nightly-builds (`1440-files-nightly.png`): Clean and fits one screen (pageScrollY 0). Three rows, no hierarchy at all: `/artifacts/manifest.json` sits next to root files as a long path. Verdict: tidy but table-like.
- 1440 Files, research-bot, key not loaded (`1440-files-researchbot.png`): 25-29 rows in an inner scroller (panel scrolls, page does not; good). Every Download is disabled and low contrast. Path prefix repeats. Verdict: below excellent.
- 1440 Files, key loaded (`1440-files-keyloaded.png`): Downloads become black outlined buttons, "KEY LOADED" badge replaces the gate, a Download recovery file button appears in the banner and pushes the panel down 2 px. Heavy: 29 outlined Download buttons. Verdict: acceptable, loud.
- 1440 Files filtered (`1440-files-filtered.png`): one row, footer jammed under it, a blank band below. Verdict: dead space.
- 1440 key-load dialog (`1440-keyload-dialog.png`, `-keyload-error.png`): works, error clear but jargon, layout jumps 33 px, key field is a black bar next to a native file input. Verdict: acceptable.
- 1440 Versions dialog (`1440-versions-dialog.png`, `-versions-multi.png`): readable, Restore buttons clear, but UUIDs and no way to view or download an old version. Verdict: acceptable.
- 1440 Trash populated (`1440-trash.png`): the Deleted date is truncated to "11/6/2026…", Recovery column truncated and constant, Modified column always "—". Verdict: poor scanning.
- 1440 Agents (`1440-agents.png`), API keys (`1440-apikeys.png`), Usage (`1440-usage.png`): consistent card/list styling. Agents has 15 full-weight "Revoke access" buttons; Usage table rules are inconsistent. Verdict: acceptable, repetitive.
- 1440 New drive, New agent, New API key dialogs (`1440-newdrive-dialog.png`, `-newagent-dialog.png`, `-newkey-dialog.png`): consistent, one primary each. New key dialog is long but fits (native select styling differs). Verdict: good.
- 1440 first visit (`1440-onboarding.png`): clear headline and one orange CTA, but duplicate "+ New drive", an external-link arrow on an in-page action, and inert step labels. Verdict: acceptable.
- 1440 receipt (`1440-receipt.png`), empty drive (`1440-empty-drive-keyloaded.png`), key not backed up banner: clear and honest; banner is a crowded one-liner.
- 1440 list error (`1440-list-error.png`, forced by rejecting fetch): raw "Failed to fetch" box, no retry, stale empty state under it. Verdict: fails.
- 768 Files, Agents, Usage (`768-files.png`, `768-agents.png`, `768-usage.png`): no overflow. Subtitle ellipsis, Author column dropped, panel title and footer wrap, rows 83 px. Verdict: acceptable with wrapping defects.
- 390 Files, Trash, API keys, nav menu (`390-files.png`, `390-trash.png`, `390-apikeys.png`, `390-navmenu.png`): top bar with "Files ▾" menu works well; Files becomes 174 px stacked cards with a 330 px toolbar before the first file; page scroll 4,784 px. Verdict: functional but a wall of cards.

## Excellent as is

- App shell: sidebar with active state, breadcrumb bar, one-screen layout at 1440 (pageScrollY 0, long lists scroll inside the panel).
- Mobile shell: top bar with "Files ▾" menu and nav overlay (`390-navmenu.png`) works and keeps the active tab clear.
- Dialog set: New drive, New agent, New API key have one orange primary each, labelled fields, plain explanatory sentence; Escape closes them and focus rings are visible (2 px black).
- Key receipt copy: states plainly what the key is, that the server cannot recover it, and gates Continue on a checkbox.
- Row hover tint and keyboard focus ring on row buttons (`focus.png` check: 2 px solid outline).
- Empty Trash and empty drive copy are short and honest.
- Version restore: "Restore creates a new current version. Existing history stays intact." is the right sentence in the right place.
- No horizontal overflow at 1440, 768 or 390 (pageOverflowX 0 on all states).
