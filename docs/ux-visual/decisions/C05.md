# C05: Mobile section nav and drive strip clip

## Problem

At 375px the console sidebar becomes a horizontal tab strip (nav scrollWidth 576 vs 343) above a breadcrumb, a horizontally scrolling drive strip (scrollWidth 662 vs 375) and the page header, about 320px before content. "Billing & limits" clips to a bare "$", "Activity & deletion" is invisible, the selected drive shows as "R", and neither strip has an overflow cue. Findings: CF-11, CS-06, CS-07 (MARKETING-09 landing nav is deferred). Evidence: `pages/console-files/shots/375x812-populated-keyloaded.png`, `pages/console-secondary/shots/375x812-usage-populated.png`. Norms: I1, I6, L2, L6, C2, D5.

Acceptance (final, see below): all 7 sections reachable and labelled; selected drive fully visible on load; no clipped labels; content at or above y=260.

## Options considered

Weighted score (max 60; criteria x3, simplicity/consistency/usability/visual x2, effort x1). Internal lenses scored by the orchestrator; external scores are the models' own (`proposals/C05/external-judges.json`).

| Option        | Idea                                              | Usability | Visual | Engineering | MUSE Wonder | Gemini Argon |
| ------------- | ------------------------------------------------- | --------- | ------ | ----------- | ----------- | ------------ |
| A Minimal     | Faded, snapping tab and bay strips                | 40        | 42     | 46          | 39          | 38           |
| B Restructure | Bottom tab bar + one drive switcher               | 47        | 45     | 38          | 42          | 40           |
| C Convention  | Current-section menu in top bar + faded bay strip | 47        | 49     | 48          | 47          | 55           |

A fails criterion 1 by the judges' reading: "Activity & deletion" is still cut mid-word at rest and the section nav still needs a swipe to discover. Both external judges vote C and both propose grafting B's single drive switcher into C.

## Decision

Adopt C (section menu in the top bar, bay strip kept) with one graft from A (fade, snap and scrollIntoView on the bay strip, already part of C) and the clipping of the selected bay fixed by width, not by B's switcher.

Rebuttal of the external graft (drive switcher): the switcher replaces a one-tap chip row with a tap plus a sheet, adds a new component and duplicate drive logic, and hides the "your next agent" add chip. The real defect is the selected bay's name being clipped. That is solved by letting the bay size to its content (`flex: 0 0 auto; max-width: min(240px, 72vw)`, name ellipsis only beyond that) and scrolling it into view. Revisit the switcher if users keep more than about 6 drives.

## Why this is the best

- Against A: removes the second horizontal scroller as the primary navigation; all 7 labels are full and visible with no swipe; no mid-word cut at rest.
- Against B: no fixed bottom bar (keyboard, page actions, safe-area), no shared-nav rework of billing and settings pages, Billing stays one tap, and the six-slot bar at 10.5px labels is avoided. Gives up 25px of height (content y=159 vs 134), still 100px under the target.
- Norms satisfied: I1 (affordance: caret and list), I6 (current section named on the control and marked in the list), L2, L6 (reflow, not overflow, for navigation), C2/D5 (breadcrumb and tab triplication removed), D3 (44px rows on the 4px scale), H4 (orange only on LED and selected bay).
- Costs: one tap to switch sections; open/close state, Escape and outside-tap handling; the bay strip still scrolls horizontally. Rules out: bottom tab bar and drive dropdown on phone for now.

## Final acceptance criteria

At 375x812 and 768x1024:

1. The phone header's nav control is a button named after the current section with `aria-expanded`; opening it shows 7 items, each with its complete text (Files, Agents, API keys, Usage, Trash, Billing & limits, Activity & deletion) and no `$` stand-in, each at least 44px tall, none clipped (`scrollWidth <= clientWidth` per item).
2. The current section is marked (`aria-current="page"` and the active style). Selecting an item closes the menu. Escape and an outside tap close it and return focus to the button.
3. After load, the selected `.bay` is fully inside the strip's visible area (`left >= strip.left` and `right <= strip.right`) with its name not ellipsised when it is up to 24 characters; the strip shows an edge fade while overflowing and snaps to chips.
4. The first content element (`.eyebrow`) top is at or below the header and at or above y=260 with the menu closed.
5. No horizontal page scroll (`scrollWidth <= innerWidth`).
6. Desktop (>=761px) is unchanged: sidebar nav always visible, no toggle button.

## Implementation plan (design system first)

1. `apps/web/app/styles/console.css`, inside `@media (max-width: 760px)` (~631):
   - `.sidebar` becomes a single flex row: `.brand` (mark only, hide the text), `.nav-toggle`, `.profile-row` (reuse the existing absolute avatar or make it static `margin-left:auto`). Remove `.sidebar nav { flex-direction: row; overflow-x: auto }`.
   - `.sidebar nav { display: none; position: absolute; left: 8px; right: 8px; top: 60px; z-index: 20; flex-direction: column; gap: 0; padding: 6px; background: var(--panel); border: 1px solid var(--line); border-radius: 12px; box-shadow: 0 18px 40px rgba(0,0,0,.28); }` and `.sidebar[data-nav-open='true'] nav { display: flex; }`.
   - `.nav-item { min-height: 44px; padding: 0 12px; font-size: 15px; gap: 12px; }`; remove the rule hiding `.nav-icon` and `.nav-count` (show both). `.nav-item.active` already inverts. Add a 1px `--line` divider above Billing (first `<Link>` of the nav; use `.nav-item[href^='/console'] ` first-of-type or a `.nav-sep` element).
   - `.nav-toggle { display: inline-flex; align-items: center; gap: 8px; height: 44px; padding: 0 12px; border: 1px solid var(--ink); border-radius: 8px; background: transparent; font: 500 14px var(--sans); }` and `display: none` at the base (desktop) rule.
   - `.topbar { display: none; }` at <=760 (breadcrumb removed).
   - `.bay-strip { scroll-snap-type: x proximity; scroll-padding: 0 16px; scrollbar-width: none; -webkit-mask-image: linear-gradient(90deg, transparent 0, #000 14px, #000 calc(100% - 40px), transparent); mask-image: same; }`, `.bay { flex: 0 0 auto; width: auto; min-width: 150px; max-width: min(240px, 72vw); scroll-snap-align: start; min-height: 44px; }`, `.bay.add { flex: none; }`. Keep `.bay-name` ellipsis.
2. `apps/web/app/(app)/console/console.tsx`:
   - `const [navOpen, setNavOpen] = useState(false);` and `<aside className="sidebar" data-nav-open={navOpen}>`.
   - Before `<nav>` add `<button type="button" className="nav-toggle" aria-expanded={navOpen} aria-controls="console-nav" onClick={() => setNavOpen(v => !v)}>{tab} <span aria-hidden>▾</span></button>`; give the nav `id="console-nav"`. The existing nav item `onClick` also calls `setNavOpen(false)`; the Billing and Settings `Link`s are navigations so need no handler.
   - Escape and outside-click: one `useEffect` while `navOpen` adding `keydown` (Escape closes and focuses the toggle) and `pointerdown` (close if outside `.sidebar`).
   - Selected bay: `useEffect(() => { document.querySelector('.bay[aria-pressed="true"]')?.scrollIntoView({ inline: 'center', block: 'nearest' }); }, [selected, drives.length, ready]);`. Do not use `block: 'center'` (it scrolls the page).
   - The `$` span in the Billing link: remove it (label reads "Billing & limits"); give the Billing and Settings links `.nav-icon` spans (`$`, `↺`) for parity with the first five.
   - The desktop render must not change, so keep the DOM identical; the toggle is hidden by CSS above 760px.
3. Landing nav (`landing.css`) stays deferred as in the problem register.
