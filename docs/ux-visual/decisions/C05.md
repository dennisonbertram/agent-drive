# C05: Unlock on demand: Download always works, one key-state signal

Review note: external MUSE Wonder and Gemini Argon judges were skipped in this run. Scores come from the three internal lenses only.

## Problem

The drive key is a precondition shown as disabled controls (29 disabled Downloads, about 2.5:1 contrast), and key state is shown three ways (badge, banner, Load/Forget) with one colour used for good and bad. The key-load dialog shifts 33 px on error and uses jargon. The key is lost on reload. Findings: F03, F07, F14. Folds ux-flow proposals 1 and 6. Acceptance criteria are C05 items 1 to 5 and 7 in `problems.md`; item 6 (remember on this device) is deferred.

## Options considered

| Option                  | Idea                                                    | Score (U / V / E) |
| ----------------------- | ------------------------------------------------------- | ----------------- |
| A Dialog + one chip     | Reuse the unlock Dialog, add a key chip                 | 51 / 52 / 49      |
| B Sheet + switcher tile | Sheet and switcher from C04-B, drop-anywhere, idle lock | 39 / 39 / 36      |
| C Lock toggle           | Locked/Unlocked toggle button                           | 51 / 41 / 41      |

## Decision

Option A, plus idle auto-lock.

1. Download is never disabled for lack of a key. Clicking it with no key opens the existing unlock `Dialog`, with the recovery-file chooser first (dashed drop target "Drop your recovery file here" optional), the pasted-key field behind a disclosure, and a reserved 20 px error line (0 px shift) with plain copy: "That recovery file is not for this drive."
2. A `pendingDownload` ref continues the action automatically after the key loads; the row shows a busy label while downloading and a toast "Saved" when finished (uses C03's Toast). The same prompt serves Share (C08) through a `pendingAction`.
3. One key chip replaces the badge, the banner and the Load/Forget button. It shows a dot and a word (colour is never the only signal): red "Key needed" or green "Key loaded"; the menu behind it holds "Download recovery file" / "Download again", "Forget key", and shows "Not backed up" until the backup is recorded, then "Key backed up" (set by C06).
4. Tokens `--ok` and `--danger` are defined once in `globals.css` and documented in `docs/design/spec-brief.md`. They are the only non-orange colours and are for status only.
5. Idle auto-lock: the key leaves memory after 30 minutes without use; a toast says the drive was locked and how to unlock.
6. Contrast of every enabled and disabled control on Files is at least 4.5:1 (disabled text at least 3:1).
7. DEFERRED to its own PR: "Remember on this device". It must be opt-in, off by default, per drive, cleared on "Forget key" and sign-out, with this plain warning beside the checkbox: anyone who can use this browser profile, or run a script on this site, can open this drive. Reason: the wrapping key would sit next to the ciphertext, so any script on the origin could decrypt it, and no Content-Security-Policy was found in `apps/web`. It only avoids a plain key in devtools storage, and A's original wording overstated that.

## Why this is the best

- Against B: depends on C04-B's Sheet and switcher tile; drop-anywhere is an extra, not a path.
- Against C: "Locked/Unlocked" is a second vocabulary beside "key" and "recovery file", and a state label that also acts as a toggle can be misread.
- Norms satisfied: errors prevented rather than disabled controls, state shown by word and colour, error text in plain language, no layout shift.
- Costs: Safari download-after-await behaviour needs checking; idle lock can interrupt a user's place (mitigated by the toast). The key stays in memory only, so a reload still requires the recovery file until the deferred PR ships.
- Rules out: disabled-for-key controls, three separate key signals, persistent key storage in this PR.

## Final acceptance criteria

`problems.md` C05 items 1 to 5 and 7, plus: idle auto-lock at 30 minutes; `--ok` and `--danger` defined once and documented in spec-brief.md; no separate banner (C06's "Key backed up" is a chip menu line). Item 6 is moved to the deferred PR.

## Test plan

- Failing first: with no key, Download is enabled and opens the prompt (fails today).
- Choosing the right recovery file starts the download with no further click; a wrong-drive file shows the reserved error with 0 px shift; the pasted-key field is behind a disclosure.
- Chip text and colour for needed/loaded; contrast check of enabled and disabled controls.
- Unit test with fake timers for the 30-minute lock.
- Safari manual check of the auto-continued download.
