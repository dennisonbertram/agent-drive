# C01: Sign-up front door and mobile marketing header

Review note: external MUSE Wonder and Gemini Argon judges were skipped in this run. Scores come from the three internal lenses only (usability, visual craft, engineering), so no external rebuttal is needed.

## Problem

The marketing header is built twice (landing and pricing differ), has no "Sign up" action, and on phones the nav is not rendered at all. The only route to a free account is "Start with Free" on /pricing. The auth cards have no link to each other. Findings: L-1, L-2, L-3, L-4, PR-2, A-1 (and A-6 as a side effect). Implements ux-flow proposal 2 and walker F-001-02. Acceptance criteria are C01 items 1 to 6 in `problems.md`.

## Options considered

Weighted scores (max 60), shown as Usability / Visual / Engineering judge.

| Option            | Idea                                                                          | Score (U / V / E) |
| ----------------- | ----------------------------------------------------------------------------- | ----------------- |
| A Minimal         | One server `SiteHeader`, `<details>` menu at 390, auth cross-link line        | 54 / 56 / 54      |
| B Shell           | Route-group layout with header and footer for /, /pricing, /sign-in, /sign-up | 54 / 52 / 52      |
| C Hamburger sheet | Client-side focus-trapping sheet, relies on Clerk footer link                 | 45 / 42 / 42      |

## Decision

Option A, plus three grafts.

1. New server component `apps/web/app/site-header.tsx` used by `/` and `/pricing`. Items: brand, Docs (`/llms.txt`, once), Pricing, text "Sign in", one orange "Sign up free". No "Console" link while signed out (signed-in shows "Open console" in place of both auth items). At 390 px Pricing, Docs and Sign in sit in a native `<details>` Menu; "Sign up free" stays outside it, at least 44 px tall.
2. Graft from B: render the same `SiteHeader` above the Clerk card on `/sign-in` and `/sign-up` (no route moves), so the auth pages stop floating.
3. Graft from B: a secondary "Create a free account" link-button in the hero next to the first Copy panel, so a visitor can decide in the hero. The final CTA also offers "Create a free account" beside the agent Copy button (criterion 6). The hero Copy stays the only orange primary in the hero; the secondary button is outlined.
4. One shared auth footer line, rendered by us under the Clerk card on both auth pages: "New here? Create a free account" or "Already have an account? Sign in", plus Pricing and Docs links. Kept even if Clerk renders its own cross-link; hide Clerk's footer link in that case.
5. Delete `.l-nav`, `.l-links`, `.billing-header`, `.billing-links*` and the 620 px `a[href='/llms.txt']` hide rule from CSS; one `.site-header` block in `globals.css`. Remove the duplicate Docs/llms.txt in the landing footer.

## Why this is the best

- Against B: the same first-time outcome (Sign up free visible at every width, one click) without moving four routes and their relative imports and Clerk catch-all routes into a route group. B's extra value, the auth frame, is taken as graft 2. B's two-row phone header costs about 44 px more height.
- Against C: a focus-trapping sheet is new JavaScript for three links, any bug there is an accessibility bug, and it relies on a Clerk footer link nobody has seen (problems.md coverage gap 1).
- Norms satisfied: one orange primary per screen (spec-brief), hairline rules, same header at all widths, touch targets of 44 px, no JavaScript for navigation.
- Costs: `/pricing` becomes dynamic if the header reads the session (loses static caching). If that matters, render the signed-out header statically and swap only the CTA on the client. The `<details>` Menu is slightly less discoverable than B's always-visible links; the one action that matters stays outside it.
- Rules out: a route-group shell for public pages, a sheet or hamburger drawer, a "Console" link for signed-out visitors.

## Final acceptance criteria

`problems.md` C01 items 1 to 6, plus: the hero has a secondary "Create a free account"; both auth pages render `SiteHeader`; the shared auth footer line is present once on each auth page (Clerk's own link hidden if it duplicates). Items 5 and 6 on real Clerk forms are verified only after a Clerk-configured run.

## Test plan

- Playwright e2e at 1440, 768 and 390: exactly one "Sign up free"; no "Console" link while signed out; Docs and llms.txt each appear once; header height and rule width equal on / and /pricing; every target at least 44 px at 390; sign-up reachable in one click from the first viewport.
- /sign-in links to /sign-up and the reverse; both link to Pricing or Docs.
- Update page-object selectors that used the old nav classes.
- Failing first: assertion that at 390 a link named "Sign up free" is in the viewport (fails today).
