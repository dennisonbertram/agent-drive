# C09: Chrome stacked above the work

## Problem
Root cause: informational blocks (drive id + key badge row, backup banner, key-info banner, key-loaded notice, a persisting status notice, and a 320px "Connect an agent" card) all render above the table or list, and key state is stated three times. Findings: CF-05, CF-08, CF-17, CF-18, CF-20, CS-01, CS-02, CS-09, CS-17, CS-21, CS-23, CS-26 (see `../problems.md` C09; evidence `../pages/console-files/shots/1440x900-populated-keyloaded.png`, `../pages/console-secondary/shots/1440x900-agents-list.png`). Presentation only: no new features, no copy rewrites beyond what is listed (nav/h1 rename CF-20 and the "YOUR NEXT AGENT" chip CS-17 stay a product decision, not done here).

## Options considered
Proposals: `../proposals/C09/{A,B,C}.md`, mocks `mock-{A,B,C}.html`, shots next to them. Measured on the mocks (first real row top, 1440x900 Files / Agents / 375 Files): A 345 / 277 / 310; B 305 / 275 / 272; C 301 / 227 / 268; all three 0px shift. Current app: 465 / about 700 / below fold.

Weighted scores (criteria x3, simplicity x2, consistency x2, usability x2, visual x2, effort x1; max 60). Usability, visual and engineering lenses were scored by the lead, one lens at a time; the two external models ran through `second-opinion.mjs` (`../proposals/C09/external-judges.json`).

| Option | Usability | Visual craft | Engineering | MUSE Wonder | Gemini Argon | Total |
|---|---|---|---|---|---|---|
| A Minimal | 47 | 49 | 56 | 56 | 49 | 257 |
| B Restructure | 32 | 38 | 35 | 35 | 31 | 171 |
| C Convention | 47 | 52 | 46 | 45 | 57 | 247 |

MUSE picked A with a graft from C (key badge into the file-panel toolbar). Argon picked C with a graft from A (native `<details>` instead of a popover). Both rank B last. These two grafts agree with each other, so the decision combines them.

## Decision
**A, with C's key-state placement and no new primitives.** Precisely:

1. Key state moves into the file panel toolbar (Files and Trash), as the existing `.badge` ("Key loaded" / "Key required for downloads") plus the existing Forget key / Load drive key button, right of "All files / {drive name}". Delete the `.drive-toolbar` row, the "You can browse file names..." info banner and the "Key loaded into page memory..." notice. The drive UUID stays in `<code data-testid="drive-id">` inside that toolbar, shown truncated (first 8 characters) with the full id in `title`. Key state is now stated once.
2. Backup status stays a `.banner.keyline` but is one 34px line (Files only): LED, one sentence, Copy, Download recovery file (when `hasKey`). Text is `white-space:nowrap; overflow:hidden; text-overflow:ellipsis` with the full sentence in `title`; at 375 the sentence wraps to two lines and the buttons go on the second line rather than truncating it. When backed up it is the same row with the dim LED.
3. `notice` becomes an inline slot on the page heading's subtitle line (replacing the subtitle while present, same line height, so no shift), with a Dismiss button. It clears on tab change, drive change and Dismiss. No timer, no toast: some notices are next steps ("Create an API key to connect it") and must not vanish. At 760px and below, where the subtitle is hidden, the same element is positioned as a fixed bottom bar (CSS only) with the same Dismiss.
4. Heading: the subtitle sits inline after the H1; the repeated eyebrow "Your agents' shared memory" is removed on console tabs (CS-23).
5. `ConnectAgentPanel` returns `<details className="panel agent-panel">` with a 38px summary "Connect an agent". It is `open` when there are no agents and no API keys, closed otherwise. Same rule at both call sites (Agents ~919, API keys ~972). The empty state is unchanged (full card).

Ruled out: toasts and popovers (new primitives), the always-on tray (B), moving Connect into a dialog.

## Why this is the best
- Against B: permanently reserved 38px chrome even when nothing is wrong, truncates the backup sentence and drops Copy at 1440, "3" chip hides state at 375 (both external judges), and needs a new component, a dialog path and priority rules. Highest effort, lowest scores from every judge.
- Against C: highest on screen (Agents row 227) and Argon's pick, but it adds Toast and Popover, and an 8s toast can vanish before the user reads a next step (WCAG 2.2.1 needs pause/extend handling). The decision takes C's one structural idea that costs nothing, key state in the panel toolbar, which also removes one of A's two rows (about 44px).
- Rebuttal to Argon on A: Argon's complaints were two stacked status bars and the unreadable truncated backup sentence at 375. Item 1 removes one bar; item 2 stops truncating at 375; item 3 keeps the notice visible at 375 as a bottom bar. Rebuttal to MUSE on C: not adopted beyond the graft.
- Norms: L1/L2 (list above the fold), L3 (nothing accumulates: the notice replaces, does not stack), L5 (no shift), C2 (key state once), D2, D5 (no 320px card when it is not needed), H1 (one primary action), T1 reference "LED plus one line".
- Costs: backup row shows an ellipsis on mid-width screens (full text in `title`); a collapsed Connect card is one click away once an agent exists; notices on mobile cover the bottom 48px until dismissed.

## Final acceptance criteria (measured with layout-audit.js / geometry-audit.js)
1. 1440x900, Files with 10 files, key loaded and not backed up: first table row top < 380 (target about 300-345); Agents and API keys with one agent and one key: first identity/key row top < 320; `scrollHeight <= innerHeight` on those tabs (page scroll owned by C01 shell fix).
2. 375x812: first row top < 520 (C05 may lower it further).
3. Setting and clearing `notice`: every element below the heading moves by <= 8px (target 0).
4. Key state text ("Key loaded" / "Key required") appears exactly once on Files and Trash; no "You can browse file names..." banner when a key is not loaded; no "Key loaded into page memory" notice.
5. Backup sentence fully readable at 375 (wraps, no ellipsis); `data-testid="key-backup-status"` and `data-testid="drive-id"` still exist.
6. Connect card: `<details>` open with zero agents and zero keys, closed otherwise; summary reachable by keyboard; its content unchanged (command, llms.txt link, three MCP snippets).
7. Notice clears when the tab or selected drive changes and has a labelled Dismiss button; `role="status"` kept.
8. Nothing is added or removed from the product's behaviour; no new component outside `console.tsx`.

## Implementation plan
Tokens: none new. CSS first: `console.css` (`.page-heading` inline sub, `.notice-slot` incl. max-width 760 fixed-bottom rule, `.banner.keyline` 34px single-line and 375 wrap, `.panel-toolbar` badge spacing); `console-panels.css` (`.agent-panel` summary row, `details[open]` spacing). Then `console.tsx`: remove `.drive-toolbar`, info banner, key-loaded `setNotice` at ~1258; add badge/Forget/Load to `.panel-toolbar` (~737); move `notice` block (~624) into the heading; `<details>` in `ConnectAgentPanel` (~126) with an `open` prop from `agents.length === 0 && keys.length === 0`; clear `notice` in the tab and drive change handlers (~331). WP1 order per `problems.md`: after C05 design decision; do not split `console.tsx` between agents.

- Trigger a notice (e.g. Forget key) and assert the first row's top moves <= 8px; switch tab and assert the notice is gone.
- Files without key: exactly one occurrence of "Key required for downloads", no `.banner.info`.
- Agents and API keys with one agent: `details.agent-panel` not open; first identity row top < 320; with zero agents it is open.
- 375x812: backup sentence not clipped (`scrollWidth <= clientWidth` on the text node), first row top < 520, notice bar visible and dismissible.
Then fresh screenshots at 1440x900, 375x812 for Files (key/no key), Trash, Agents, API keys.
