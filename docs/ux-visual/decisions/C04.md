# C04: Console as a cloud-drive file browser (also covers C14)

Review note: external MUSE Wonder and Gemini Argon judges were skipped in this run. Scores come from the three internal lenses only.

## Problem

The Files tab is a flat log table of full paths, built for agents writing files. There is no hierarchy, sort, selection, file types or Recent view, the page's only primary button creates a drive, and the drive strip repeats on account tabs (74 px). On phones rows are 174 px tall. Findings: F01, F02, F06, F11, F12, F18, F20. Folds ux-flow proposal 4, walker F-019-01 and F-022-01, and C14. Acceptance criteria are C04 items 1 to 9 and C14 in `problems.md`.

## Options considered

| Option                | Idea                                                               | Score (U / V / E) |
| --------------------- | ------------------------------------------------------------------ | ----------------- |
| A Table + hierarchy   | Keep panel and table; breadcrumb, folder rows, sort, icons, Recent | 49 / 51 / 46      |
| B Tree + details pane | Three panes, folder tree, details pane                             | 41 / 33 / 36      |
| C Drive/Dropbox model | Rail views, drive dropdown in the title, "+ New", FAB              | 54 / 46 / 45      |

## Decision

Option A, with grafts from C and the engineering judge's loading rules.

1. Folders are derived client-side by a pure `file-tree.ts` (unit tested) from loaded rows. A folder row shows icon, name and item count. Files show their name only, no repeated path prefix.
2. Breadcrumb above the list. At the root, its first segment is the drive name with a dropdown that switches drive and holds "New drive". This replaces the drive strip; account-level tabs (Agents, API keys, Usage) show no drive.
3. View switcher `Browse | Recent | Shared` as a general control. State is in the URL: `?path=` and `?view=`, so reload and back work. Recent uses the existing `recent` event API and dedupes by path. Shared is built in C08.
4. Sortable headers Name, Modified, Size; default Modified newest first; arrow shows state; keyboard operable. File-type icon on every file row.
5. One orange primary "Connect an agent" (acts on files while agents write all files). "New drive" is secondary, inside the drive dropdown. No Upload in this phase.
6. Open the last-used drive, remembered in `localStorage` (reads and writes in try/catch; fall back to the first drive).
7. Phone (390 px): 56 to 60 px two-line rows (name; size and date), always-visible "⋯" (44 px target), tapping the row starts Download (through the C05 unlock prompt). No hover-only actions; no floating button.
8. Loading: the API returns full paths, 100 per page, and `prefix` is a recursive LIKE. Inside a folder, pass `prefix` to narrow the fetch. Load pages up to a cap of about 1,000 rows and show "Showing first N" when capped. Counts and Modified sort are labelled as over loaded rows. Row states use C02's `<ListState>`.
9. Remove filler subtitles and footer copy (F20); keep the encryption/metadata footer line from C02.
10. No page-level scroll at 1440x900; the list scrolls inside its panel.

## Why this is the best

- Against C: C's split button, FAB, lock button and rail reordering are new patterns not in the spec sheet, and its "+ New" default of "Connect an agent" is a mismatched label that reads as Upload. We take its drive dropdown, view in URL and 56 px rows. The usability judge preferred C (54 vs 49); the visual and engineering judges preferred A (51 vs 46, 46 vs 45); the grafts close the usability gap.
- Against B: three scrolling regions in a 1280x800 console, a tree with lazy prefix loads, and a `console.tsx` split while C02 and C03 are editing it. Effort L.
- Norms satisfied: familiar file-manager model (breadcrumb, folders, sort), URL state, one primary action, touch targets of 44 px, dense console within 1280x800.
- Costs: counts and Modified sort are only as accurate as the loaded rows (labelled); the 1,000 cap hides rows beyond it; inline preview is phase 2.
- Rules out: tree pane, details pane, FAB, upload in this phase.

## Final acceptance criteria

`problems.md` C04 items 1 to 9 as amended above (drive dropdown replaces the strip, `?view=` includes Shared), and C14: at 390 a file row is at most 64 px, at least 8 files visible on the first screen, toolbar before the first file at most 120 px; at 768 no truncated subtitle or wrapping panel title or footer. "Showing first N" notice appears when capped.

## Test plan

- Unit: `file-tree.ts` (folder derivation, counts, item names, dedupe of Recent).
- Playwright at 1440, 768 and 390: breadcrumb navigation, URL round trip, sort by each header with keyboard, pageScrollY 0 at 1440x900, row height and first-screen count at 390, last-used drive after reload, localStorage failure falls back.
- Failing first: assertion that no row title contains the repeated path prefix.
- Seed test with more than 1,000 files for the cap notice.
