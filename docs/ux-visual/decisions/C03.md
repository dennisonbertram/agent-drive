# C03: File-row actions and feedback where the action happens

Review note: external MUSE Wonder and Gemini Argon judges were skipped in this run. Scores come from the three internal lenses only.

## Problem

Row actions are three equal-weight text links (Trash is 46x28 next to Versions; two files were trashed by mis-click). Results appear in the page header, far from the row. There is no toast and no undo, native `confirm()` is used for revoke, the Versions dialog shows UUIDs and seconds, and a revoked agent still shows "Revoke access" at 0 keys. Findings: F04, F15, part of F13. The receipt-dialog finding F17 and its criterion are owned by C06 and are dropped here. Acceptance criteria are C03 items 1 to 5 in `problems.md`.

## Options considered

| Option                            | Idea                                                                 | Score (U / V / E) |
| --------------------------------- | -------------------------------------------------------------------- | ----------------- |
| A Toast + overflow + confirm      | Download plus a menu, toast with Undo, named confirm                 | 51 / 53 / 49      |
| B Selection + action bar + drawer | Row selection, bulk bar, Versions drawer                             | 39 / 39 / 36      |
| C Drive/Gmail convention          | Same design as A with Drive/Gmail wording and Dropbox version labels | 51 / 51 / 53      |

## Decision

Option A's design and implementation, with C's wording and menu rules.

1. Each file row shows Download and an always-visible "⋯" menu button (never hover-only). The menu holds Versions, Share (C08) and, last under a divider, Trash as a danger-coloured item (`--danger`). Hit area at least 32 px high, 44 px on touch. The menu is the shared one used by C04; keyboard arrows, Escape and focus return are required.
2. New `Toast` component, bottom-left, within the viewport at 1440 and 390, at least 8 s, appears synchronously. Trash is optimistic: the row leaves the list at once and the toast reads "Moved 'name' to Trash" with Undo; if the API call fails, the row returns and an error toast shows (rollback). Undo captures the original drive id in its closure so it works after a drive switch. Restore from Trash and a version restore show "Restored 'name'" with "Show file" (Drive wording).
3. New `ConfirmDialog` built on the existing `Dialog` (console.tsx:203), replacing native `confirm()`. Revoking an agent names the agent and the number of active keys. After revoke the row moves to a Revoked state in place; no "Revoke access" at 0 keys.
4. Versions dialog (Dropbox style): rows read "Current version · today 14:02 · 4.2 KB · author"; older rows show relative date, size and author; no UUID in the default view; a single-version file says "This is the current version".
5. Trash notice that share links stop working is owned by C08 (confirm only when the file has active links).
6. Dropped: C03 criterion 6 (receipt dialog), owned by C06.

## Why this is the best

- Against B: selection, a bulk bar and a drawer are three new patterns that depend on C04 row selection; bulk undo has partial failures; single-file Trash becomes two steps, slower for the common case.
- Against C alone: A has the concrete failure handling (rollback, closure-captured drive id, `ConfirmDialog` reuse); C supplies the wording and menu ordering, which are merged in.
- Norms satisfied: feedback near the action, undo over confirm for reversible actions, destructive action separated from the primary action, always-visible controls for touch.
- Costs: native popover has no arrow-key handling, so the menu needs keyboard code. Optimistic update needs rollback tests.
- Rules out: hover-only actions, bulk selection in this phase, a Versions drawer.

## Final acceptance criteria

`problems.md` C03 items 1 to 5 with the wording above; item 6 (receipt) removed. Toast at least 8 s.

## Test plan

- Failing first: Playwright asserts the toast with Undo appears after Trash within 100 ms (fails today).
- Undo restores on the original drive after switching drive; API failure rolls the row back and shows an error toast.
- Menu opens and closes by keyboard; no destructive item within 8 px of another action; target heights at 1440 and 390.
- Revoke: ConfirmDialog names the agent and key count; row shows Revoked in place.
- Versions dialog shows no UUID; single version shows "This is the current version".
