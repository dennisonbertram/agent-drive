# C03: Wide tables unreachable on phones

## Problem
Five tables (Files, Trash, Usage by author, billing Usage by agent, settings Audit log) keep a 620-1851px intrinsic width inside a 293-341px `.table-scroll` at 375px, with no scroll cue. Size, author, Download, Restore and the usage/audit columns are off-screen. Findings: CF-03, CS-03, CS-04, CS-24, ACCOUNT-06, ACCOUNT-07. Root cause: `min-width` (720 in `console.css` 760px block, 630 in `account.css` 700px block), `white-space:nowrap` cells, and no reflow under 760px. Violated norms: L6 (reflow, not overflow), L2, I1.

Acceptance criteria as filed: (1) at 375 the primary action of each row (Download, Restore) is visible without sideways scroll; (2) no table scroller is wider than 1.3x its box unless a visible scroll cue is present; (3) no mid-word clipped action text.

## Options considered
Mocks and full proposals: `proposals/C03/{A,B,C}.md`, `mock-{A,B,C}.png`, `mock-final.png` (the chosen design). Weighted score, max 60 (criteria x3, simplicity x2, consistency x2, usability x2, visual x2, effort x1).

| Option | Idea | Usability | Visual | Engineering | MUSE Wonder | Gemini Argon |
|---|---|---|---|---|---|---|
| A Minimal | Hide columns 2-4, scroll shadow, shrink usage tables | 36 | 33 | 40 | 2/5/2/2/2/5 = 36 | 2/4/2/2/1/5 = 31 |
| B Restructure | Stacked row records under 760px, labelled lines, visible actions | 52 | 50 | 52 | 5/4/5/4/4/3 = 52 | 5/4/5/4/5/4 = 56 |
| C Convention | Flat list rows, dotted meta line, filled primary + overflow menu | 42 | 44 | 37 | 4/3/2/3/4/2 = 37 | 4/2/3/3/3/2 = 39 |

External scores are the models' per-criterion numbers (criteria/simplicity/consistency/usability/visual/effort) weighted the same way. Both external judges chose B. Raw output: `proposals/C03/external-judges.json`.

## Decision
Option B, with one graft from C and one tweak from Argon. At `max-width: 760px` every data table becomes a list of stacked records, one shared class, `.table-stack`, no per-table CSS:
- Records are flat, divided rows inside the existing panel (1px `--line-soft` bottom border, 12px 14px padding), not nested bordered cards. This is the graft of C's flat divided-row treatment, suggested by Argon and MUSE; it cuts the mock from 2701px to 2431px and removes card-in-card borders.
- The first cell is the record title (wraps, never ellipsised). Other cells are `label (mono 10.5px caps, muted) ... value (right-aligned)` lines, labels from `data-label`.
- Files/Trash records end with an actions row of 40px-high buttons. The first button (Download, Restore) has a 1px ink border and weight 600; the others have a `--line` border. No filled black buttons, so a column of records does not break "one high-emphasis button per region" (Argon's point).
- `thead` stays in the DOM, visually hidden (not `display:none`), and rows get ARIA roles so table semantics survive `display:block`.
- Desktop (>760px) is unchanged. The old `min-width` rules are deleted.

Not adopted: MUSE's suggestion to use C's dotted-meta rows for the read-only tables. It would need a second render path per table and make five tables look like two patterns (Argon also rejected it). C's `<details>` overflow menu is not adopted: it hides Trash and Versions, overlaps the next row, and needs JS to close.

## Why this is the best
- Against A: A removes size/author/modified on phones (data loss) and in the mock still breaks words ("RETA/INED", "SUCCES/S", "FAILUR/E", "file.ve/rsion.c/reate"), so it fails criterion 3 in spirit. File names are ellipsised, and the T1 reference does not drop columns on mobile. A is cheaper (about 40 lines, no markup) but only moves the problem.
- Against C: C is more compact (1622px) but hides Trash/Versions behind an overflow menu, makes Download a filled button on every row, wraps its meta line with orphaned dots, needs two render paths and a menu to test, and is an L-effort invention against the T1 card reference. The gain (about 800px of height) is mostly recovered by the flat-row graft.
- Norms satisfied: L6, L2, H1 (outline buttons), H5 (one pattern for all five tables), D1 (labels 10.5px mono match table headers), I1 (every action visible), T1 reference (`@media (max-width:860px) table,thead,tbody,tr,td{display:block}`).
- Costs: about 2.5x vertical space per row on phones; a file takes roughly 150px. Rules out per-column sorting UI on phones (none exists today). Needs `data-label` strings kept in sync with `<th>` text (duplicated strings, acceptable).
- Unverified: mocks are static HTML; real behaviour in the app (focus order, `role` interaction with `tabIndex` on the audit region) is not yet observed.

## Implementation plan
Order: tokens/CSS, then markup. WP0 (`globals.css`) before WP1/WP2 as in problems.md.

### 1. `apps/web/app/globals.css` (add near `.table-scroll`, ~line 377)
```css
@media (max-width: 760px) {
  .table-scroll.table-stack { overflow: visible; }
  .table-stack table,
  .table-stack tbody,
  .table-stack tr,
  .table-stack td { display: block; width: auto; }
  .table-stack thead {            /* keep column names for screen readers */
    position: absolute; width: 1px; height: 1px; overflow: hidden;
    clip: rect(0 0 0 0); white-space: nowrap;
  }
  .table-stack table td {         /* (0,1,2) beats .file-panel td and .billing-page td (0,1,1) */
    display: flex; justify-content: space-between; align-items: baseline; gap: 12px;
    min-width: 0; max-width: none; padding: 3px 0; border: 0;
    white-space: normal; overflow: visible; text-overflow: clip;
    overflow-wrap: anywhere; text-align: right;
    font: 400 12.5px/1.5 var(--mono, 'IBM Plex Mono', ui-monospace, Menlo, monospace);
  }
  .table-stack table td::before {
    content: attr(data-label); flex: none; text-align: left;
    font: 500 10.5px var(--mono, 'IBM Plex Mono', ui-monospace, Menlo, monospace);
    letter-spacing: 0.05em; text-transform: uppercase; color: var(--muted, #5d5b56);
  }
  .table-stack table tr {
    display: block; padding: 12px 14px;
    border-bottom: 1px solid var(--line-soft, rgba(18, 18, 17, 0.09));
  }
  .table-stack table tr:last-child { border-bottom: 0; }
  .table-stack table td.primary {  /* title: wraps, no label */
    display: block; padding: 0 0 6px; text-align: left;
    font-weight: 500; font-size: 13px;
  }
  .table-stack table td.primary::before,
  .table-stack table td.actions::before { content: none; }
  .table-stack table td.actions { display: block; padding: 8px 0 0; text-align: left; }
  .table-stack small { display: block; text-align: right; }
}
```
`.primary`/`.actions` only change anything inside `.table-stack`, so the class names are safe on desktop.

### 5. Markup
`console.tsx` Files/Trash table (~748): `<div className="table-scroll table-stack">`. First `<td className="file-cell primary">`. Subsequent tds: `data-label={tab === 'Trash' ? 'Deleted' : 'Size'}`, `data-label={tab === 'Trash' ? 'Recovery' : 'Author'}`, `className="modified" data-label="Modified"`, final `<td className="actions">`. The empty filter row `<td colSpan={5} className="primary">` (no label).

`console.tsx` Usage by author (~1117): `table-scroll table-stack`; first td `className="primary"`; then `data-label="Storage"`, `"Versions"`, `"Operations"`.

`billing-client.tsx` (~510): `table-scroll table-stack`; first td `className="primary"`; `data-label="Retained"`, `"Downloads"` (the long "Not metered..." text wraps right-aligned), `"Operations"`.

`settings-client.tsx` (~242): `table-scroll table-stack` (keep `ref`, `role="region"`, `aria-label`, and `tabIndex={0}` only while the table overflows at >760; at <=760 nothing scrolls so `tabIndex` is harmless but can stay). Reorder cells so the action code is first: `<td className="primary"><code>…</code></td>` then `data-label="When"`, `"Actor"`, `"Result"`. On desktop the column order must not change: instead of moving the cell, keep order When/Action/Actor/Result and give the Action `<td>` the `primary` class and `order: -1` in the stack CSS (add `.table-stack table td.primary { order: -1 }` and `.table-stack table tr { display: flex; flex-direction: column; }` for this table only via `.settings-audit`). Simplest: in `account.css` add inside `@media (max-width:760px)`: `.settings-audit tr { display: flex; flex-direction: column; } .settings-audit td.primary { order: -1; }`. The When cell then gets `data-label="When"`.

Add `role="table"` on each `<table className…>`, `role="row"` on each `<tr>`, `role="cell"` on each `<td>`, `role="columnheader"` on `<th>`, `role="rowgroup"` on thead/tbody. (Safari/VoiceOver drops table semantics from `display:block`; harmless elsewhere.)

## Final acceptance criteria
1. At 375x812, for Files (populated, key loaded), Trash, each row's Download or Restore button has a bounding box inside the viewport width (`left >= 0`, `right <= 375`) with no horizontal scrolling.
2. At 375, for all five tables: `document.documentElement.scrollWidth <= 375`, and `.table-scroll.scrollWidth <= clientWidth` (no overflow; the 1.3x/cue clause holds trivially).
3. No action text is clipped: for each button in `.row-actions`, `scrollWidth <= clientWidth`; no cell has `text-overflow: ellipsis` active at <=760.
4. Every record shows all its fields (Files: size, author, modified; Trash: deleted, recovery; usage: storage, versions, operations; billing: retained, downloads, operations; audit: when, actor, result).
5. Action buttons and rows in the stack are at least 40px high.
6. At 761px and above (768, 1440, 1920) the tables look as before (`thead` visible, `display:table`).
7. Column names remain available to assistive tech (thead present, roles set).
