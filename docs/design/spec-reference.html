Portable storage for agents

Agent files that outlive the sandbox.

Agents save to their drive as they work. When the sandbox ends, the machine changes, or the work moves from Claude Code to Codex, the files are still there.

The problem

Sandboxes end. Machines change. Platforms switch.

Each one wipes whatever the agent saved locally, and the next run starts from zero. With a drive, the agent picks up where it stopped.

What it unblocks

Work that is bigger than one session.

Research

An agent gathers sources and notes over days. Each run starts from what the last one found, not from an empty sandbox.

Long-running goals

A goal that takes weeks survives restarts, new machines and new models. The plan and the progress live in the drive.

Many agents, one drive

Agents in separate sandboxes read and write the same files. Every version records which agent wrote it. Each agent has its own key, and its writes can be limited to folders. A conditional write to a file another agent just changed fails with a conflict. Agents catch up on changes with recent --wait 60 --drive "$DRIVE_ID".

Features

Encrypted. Sharable. Works anywhere.

Encrypted

Files are encrypted on the agent's machine with AES-256-GCM. We store only ciphertext and never see your drive keys.

Sharable
$ agent-drive share --drive "$DRIVE_ID" /outputs/report.pdf --expires-in 7d

An expiring link that decrypts in the recipient's browser. No account needed, and you can revoke it.

Works anywhere
$ export AGENT_DRIVE_CREDENTIALS=adcred1.…

A CLI and an MCP server. Set the credentials as a secret in any sandbox, laptop or CI runner and the agent has its drive.

Example

A bot, a coder and an assistant on the same data.

Three agents on three platforms. None of them shares a machine. They meet in the drive.

1 / Grok bot · cloud worker

Pulls today's posts about your app from X.

$ agent-drive put --drive "$DRIVE_ID" posts.jsonl /inbox/x/2026-11-05.jsonl

Reads the posts, builds the feature people asked for most, and writes up what changed.

$ agent-drive get --drive "$DRIVE_ID" /inbox/x/2026-11-05.jsonl
$ agent-drive put --drive "$DRIVE_ID" notes.md /outputs/csv-export.md

Checks what changed through the MCP server and tells you.

No API key to copy.

Three ways to add a second agent to a drive

  • •Approve it in the browser.

    Paste the same line into it, then on /connect choose the drive and supply its key (credentials bundle or recovery file).

  • •Give a sandbox a .env line.
    agent-drive credentials issue --name devin --drive "$DRIVE_ID" --to sandbox.env
  • •Hand it over from an agent that has the drive.
    agent-drive grant CXRH-TZJT

    The granting agent needs the delegate permission. You approve once at /connect.
