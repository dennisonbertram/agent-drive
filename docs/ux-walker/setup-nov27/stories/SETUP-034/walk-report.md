# SETUP-034 walk report: Maya creates her own drive and saves the recovery file

Environment: local release 0.5.1 copy, test-session user `e2e_owner_keys_5` (final run). Viewport 1280x800 plus one 390x844 check. CLI run on the Mac Studio with `AGENT_DRIVE_API_URL=http://localhost:3811/api`.
Harness notes (not product findings): the shared dev server did full page reloads at random times during the first three attempts, which wiped the in-tab key and once navigated my tab to another walker's /connect page. The final run used user 5 and finished cleanly. Clerk sign-in is not walkable here; recovery-file download to the OS Downloads folder and 1Password steps are not walkable (the file picker could not be used, so the key was pasted instead).

## Steps
1. Open /console (screenshots/step-1.png). Onboarding panel "Give your first agent a home." with Copy line, 3 numbered steps, and "Prefer to set up a drive yourself? New drive". The heading banner also offers "Set up" (passphrase). Two calls to action; the banner link is small and underlined, the panel is clear. Geometry: no overflow; `ol.onboarding-steps` columns 190/204/134 wide (content driven, fine). Pass with a minor hesitation (what is "Set up"?).
2. Click New drive (step-2.png). Dialog "Create a drive", name prefilled and selected "my-drive", checkbox "Agent-only - never add this drive to passphrase unlock" with no explanation. Looks clean. Hesitation on the checkbox wording.
3. Type name, Create drive (step-3.png). Dialog "Your drive. Your key." with collapsed "Show drive key", warning, one primary button. Key chip behind it already says "Key loaded - Not backed up". Pass.
4. Show drive key (step-4.png, step-5.png). Black textarea 76px tall for a one-line 43-char key; a small "Copy" button sits about 2px under it. Copy exists and is not warned about plaintext on the clipboard. Esc and the backdrop do nothing; no close control (verified): the user can only download. Layout acceptable, slightly crude.
5. Download recovery file and continue (step-5.png). Dialog adds "Did the recovery file save?" with `I saved it` (primary) and `Download again`. Dialog grows to about 570px tall and stays on top of the open key panel. Pass.
6. I saved it (step-6.png). Dialog closes, banner text replaced by "Recovery file saved. Store it in a password manager. Dismiss". The "Set up" passphrase banner is hidden while this notice shows. Chip "Key loaded" (green). The drive picker button reads "research-no..." (truncated; measured 109.7px wide vs 124px content). Fail on text fit (low).
7. Key chip menu (step-7.png). "Key loaded in this tab." / "Key backed up 11/27/2026 (file)" / Download recovery file again / Forget key / Set up passphrase unlock. Clear. "Forget key" has no explanation next to a reassurance-style menu.
8. Empty state "Ready for your first file. Connect an agent with the CLI or MCP to upload encrypted files." Pass.
Mobile (mobile-check.png): no horizontal overflow, menu overlays the toolbar, notice pinned at bottom. Script flagged wrapped controls (nav toggle, drive button, Browse/Recent/Shared); screenshot shows single-line labels, so false positives.
9. CLI `login --name claude-code` prints link, code check, "Verification code: 442c 93ea debb 6aa5", "Waiting for approval...". (With the task-given URL without /api the CLI said only "Agent Drive refused the login request: 404".)
10. /connect (step-10a.png, step-10b.png, step-10c-no-key-error.png, step-10d.png). Details must be opened first; then a small underlined link "Use one of my drives instead (needs its recovery file)". The form shows Drive, Drive key, Or choose a file, Read only, Only allow writes under, Use a new drive instead, Verification code. Submitting without a key shows inline "Paste the drive key or choose a recovery file." (good). With the key pasted for an empty drive the result page says "Access approved for claude-code ... This drive has nothing to check the key against, so it could not be checked before sending." Works. Form grid: "Only allow writes under (optional)" sits next to the Drive select and the Drive key next to Choose a file, so visual reading order differs from tab order; its label wraps to two lines. Drive select defaults to the first drive (the one with no key in this tab).
After approval the CLI printed: "Logged in as agent claude-code." then "Your account has no account key yet, so the console cannot open this drive. Set a passphrase in the console under Settings; agents will add the drive then." and `agent-drive check` failed with "drive key not backed up: <id>" plus the credentials-export hint, although the owner had saved the recovery file in the console.

## Flow Log
- Ideal path: 4 steps (New drive, Create drive, Download and continue, I saved it). Actual: 4 plus one optional reveal. Matches.
- Hesitations: "Set up" banner vs New drive; Agent-only checkbox; Copy drive key (no warning); no way to close the receipt.
- Re-entry: on /connect the user must re-type the verification code and re-supply the key/file even though the console had just handled the same key.
- Duplicated info: backup status exists in console (chip/menu) and in CLI (`check`), and they disagree after step 10; the login output tells the user to set a passphrase to open a drive they already hold the file for.
