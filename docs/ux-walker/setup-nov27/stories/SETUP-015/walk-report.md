Copy button; checkbox "I saved my API key securely" gates `Done` (disabled until ticked). Good. The dialog says "use it with agent-drive login" and not how.
10. Terminal. (a) Story command: `printf '%s' "<key>" | agent-drive login --api http://localhost:3811/api --token-stdin` printed a single line of whoami JSON (accountId, agentId, keyId, scopes, driveIds...), exit 0, no "Logged in" sentence, no config path, no next step. (b) The console's own snippet (`AGENT_DRIVE_API_KEY=... agent-drive login --api http://localhost:3811`) printed the same JSON. (c) `whoami` then shows `"localDriveKeys":{"<drive id>":false}`.
11. `agent-drive check` -> "There is no usable drive key on this machine. Run `agent-drive login` again." (misleading: login again cannot create the key the user already made in the browser).
12. `agent-drive credentials import --from <the recovery file the console just made>` -> "Not a valid Agent Drive credentials bundle." The console's recovery file (agent-drive-key-v1) is not accepted by the CLI; the error does not say which file type is expected or how to use the recovery file.
13. What works: set the drive key as `AGENT_DRIVE_KEY` (the console snippet's second `read` line): `check ok drive=<id>`; `put h.md /memory/h.md --drive <id>` succeeded. This route is not in `agent-drive --help` (which lists only AGENT_DRIVE_CONFIG, API_URL, API_KEY, MACHINE, CREDENTIALS).
14. `--token-stdin` outside login: "--token-stdin is only supported by `login`." Clear. Piping a key without `--token-stdin` (starts device flow) not walked: device-flow starts were rate-limited at that moment.
15. Mobile 390x844 API keys page (mobile-check.png): no overflow, code block wraps (long lines break mid-flag), acceptable. A collapsed "Connect an agent" box above the key list renders as an empty-looking bordered bar.
